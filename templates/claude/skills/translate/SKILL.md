# Translate

Добавляет новую локаль в проект, где переводы лежат в директориях `*.i18n`, а эталоном служит `en.js`. Клод сам
выступает переводчиком — внешний API не нужен: читает `en.js`, переводит только человекочитаемый текст с сохранением
ICU-синтаксиса и структуры, и пишет `<lang>.js`.

## Вход и выход

- **Директория перевода** — любая папка с суффиксом `.i18n` (например `header.i18n`, `checkout.i18n`).
- **Эталон** — `en.js` внутри такой папки: ES-модуль вида `export default { ... }`, где значения — строки в формате ICU
  MessageFormat.
- **Результат** — файл `<lang>.js` рядом с `en.js`: та же структура и ключи, но переведённые значения. Формат тот же:
  `export default { ... }`.

`<lang>` — код целевого языка (`de`, `fr`, `es`, …). Для китайского используй `zh-CN` (материковый Китай).

## Алгоритм

1. Определи целевой язык из запроса пользователя (код локали).
2. Найди все директории `*.i18n` в проекте, **исключая** `node_modules`:
   ```bash
   find . -type d -name '*.i18n' -not -path '*/node_modules/*'
   ```
3. Для каждой директории применяй правила пропуска (ниже).
4. Для не пропущенных: прочитай `en.js`, переведи, запиши `<lang>.js`.
5. По завершении кратко отчитайся: сколько папок переведено, сколько пропущено и почему.

## Правила пропуска (соблюдай строго)

- `<lang>.js` **уже существует** → пропусти папку, не перезаписывай без явной просьбы.
- `en.js` **отсутствует** → пропусти папку.
- В `en.js` нет `export default` с объектным литералом → предупреди о неверном формате и пропусти.

## Правила перевода ICU (ключевое для качества)

Переводи **только свободный человекочитаемый текст**. Синтаксис ICU и код не трогай:

- **Ключи объекта** — идентификаторы, НЕ переводить.
- **Имена аргументов** внутри `{…}` — НЕ переводить: в `{count, plural, …}` слово `count` остаётся как есть.
- **Служебные слова ICU** — НЕ переводить: `plural`, `select`, `selectordinal`, форматтеры `number`/`date`/`time` и их
  спецификаторы (`percent`, `short`, `currency`, …).
- **Символ `#`** внутри plural сохраняется.
- **Rich-text и теги** (`<b>…</b>`, `<link>…</link>`, `<0>…</0>`) — сами теги сохраняй, переводи только текст между
  ними.
- **Не-строковые значения** (числа, булевы) и вложенные объекты — сохраняй; переводи только строки, структуру повторяй
  полностью.

### Категории plural зависят от языка

Варианты plural (`one`, `few`, `many`, `other`, …) должны соответствовать CLDR-правилам **целевого** языка, а не
английского. Пример: `{count, plural, one {# item} other {# items}}` при переводе на русский становится
четырёхвариантным, а на китайский — одновариантным.

| Язык                   | Категории plural                 |
|------------------------|----------------------------------|
| ru, uk, pl             | one, few, many, other            |
| de, es, it, nl, pt, sv | one, other                       |
| fr                     | one, many, other                 |
| zh, ja, ko, vi, th     | other                            |
| ar                     | zero, one, two, few, many, other |

Если не уверен в категориях языка — бери `other` как основную и добавляй остальные согласно CLDR этого языка.

## Формат вывода

Файл `<lang>.js` должен:

- начинаться с `export default ` и содержать объектный литерал;
- в точности повторять набор и порядок ключей `en.js`;
- быть валидным ES-модулем (корректные кавычки и запятые).

**Пример (`en.js` → `de.js`):**

Input `en.js`:

```js
export default {
	greeting: 'Hello, {name}!',
	inbox: {
		unread: '{count, plural, one {# message} other {# messages}}',
	},
	checkout: 'Proceed to checkout',
}
```

Output `de.js`:

```js
export default {
	greeting: 'Hallo, {name}!',
	inbox: {
		unread: '{count, plural, one {# Nachricht} other {# Nachrichten}}',
	},
	checkout: 'Zur Kasse',
}
```

`{name}`, `count`, `plural`, `#` и структура сохранены; переведён только текст, а plural-текст просклонён по правилам
целевого языка.
